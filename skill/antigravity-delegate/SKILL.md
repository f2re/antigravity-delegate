# Antigravity Delegate

Используй `scripts/antigravity_delegate.py` как единственную точку запуска `agy`. Не формируй прямую shell-команду `agy -p` самостоятельно, если runner доступен.

## 1. Предварительная проверка

Определи каталог этого `SKILL.md` как `SKILL_DIR`, затем выполни:

```bash
python3 "$SKILL_DIR/scripts/antigravity_delegate.py" doctor --pretty
```

При первом использовании или после смены учётной записи выполни проверку авторизации:

```bash
python3 "$SKILL_DIR/scripts/antigravity_delegate.py" doctor --probe-auth --pretty
```

Если авторизация отсутствует, остановись и сообщи пользователю, что ему нужно один раз запустить `agy` интерактивно и пройти официальный вход Google. Не запрашивай и не принимай токены в сообщении.

## 2. Классифицируй задачу

Выбери ровно один профиль:

- `architecture-reviewer` — архитектура, связность, технический долг;
- `security-reviewer` — безопасность, права, секреты, опасные операции;
- `test-auditor` — тесты, CI, воспроизводимость;
- `researcher` — спецификации, документация, сравнение вариантов;
- `implementation` — ограниченное изменение кода.

Выбери режим:

- `read-only` — любой аудит, обзор или исследование;
- `isolated-write` — только когда Antigravity должен менять файлы.

Runner требует чистый исходный Git-репозиторий. Не прячь и не сбрасывай пользовательские изменения автоматически. При грязном репозитории остановись и покажи файлы, мешающие безопасному запуску.

## 3. Подготовь задание

Задание должно быть самодостаточным. Включи:

1. цель и критерий завершения;
2. конкретные каталоги, файлы и точки входа;
3. ограничения на изменение файлов;
4. обязательные проверки;
5. формат доказательств `путь:строка`;
6. запрет на commit, push, deploy, производственные миграции и работу с секретами.

Не передавай `.env`, пароли, токены, закрытые ключи, персональные данные и содержимое пользовательских каталогов.

Для длинного задания создай временный текстовый файл с правами только владельца и передай его через `--task-file`. После получения результата удали временный файл.

## 4. Запусти read-only задачу

```bash
python3 "$SKILL_DIR/scripts/antigravity_delegate.py" run \
  --workspace "$REPO_ROOT" \
  --profile architecture-reviewer \
  --mode read-only \
  --task-file "$TASK_FILE" \
  --timeout 15m \
  --pretty
```

Runner сам создаёт одноразовый detached `git worktree`. Если Antigravity изменит хотя бы один файл, итоговый статус будет `POLICY_VIOLATION`, а временный worktree будет удалён.

## 5. Запусти изменяющую задачу

```bash
python3 "$SKILL_DIR/scripts/antigravity_delegate.py" run \
  --workspace "$REPO_ROOT" \
  --profile implementation \
  --mode isolated-write \
  --task-file "$TASK_FILE" \
  --timeout 30m \
  --pretty
```

При наличии изменений runner возвращает:

- `execution_worktree` — отдельный рабочий каталог;
- `branch` — отдельную ветку `agy/...`;
- `changed_files` — фактически изменённые файлы;
- `diff_check` — результат `git diff --check`.

Не переноси изменения автоматически только потому, что `status=SUCCESS`.

## 6. Обязательная проверка Codex

После каждого запуска:

1. Проверь верхнеуровневый `status` runner.
2. Проверь `agy_result.status`.
3. Прочитай `agy_stderr_tail` и `cleanup_warnings`.
4. Для read-only сопоставь вывод с кодом и первичными источниками.
5. Для isolated-write открой `execution_worktree`, выполни `git status`, `git diff --check`, прочитай полный diff и запусти проверки проекта.
6. Исправь ошибки самостоятельно либо отправь Antigravity новое ограниченное задание.
7. Переноси в основную рабочую ветку только проверенные изменения.
8. После переноса удали отдельный worktree и ветку штатными командами Git.

Никогда не сообщай пользователю, что вывод внешнего агента подтверждён, пока не проверил его.

## 7. Модель и custom agent

Не угадывай название модели. При необходимости сначала выполни `agy models`, затем передай точный slug через `--model`. Headless-режим Antigravity не должен молча подменять неизвестную модель.

Параметр `--agent` используй только если соответствующий custom agent уже установлен и отображается в `agy agents`. Встроенный `--profile` работает без установки custom agents.

## 8. Запреты

- Не используй `--dangerously-skip-permissions`: runner намеренно не предоставляет этот параметр.
- Не запускай Antigravity в основном checkout для изменяющей задачи.
- Не делегируй commit, push, merge, deploy, публикацию пакетов и производственные миграции.
- Не разрешай широкие правила `command(*)`, `read_file(*)`, `write_file(*)`, `read_url(*)` без отдельного решения пользователя.
- Не выполняй несколько изменяющих заданий в одной ветке или одном worktree.
