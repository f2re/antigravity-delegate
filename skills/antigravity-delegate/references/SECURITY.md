# Модель безопасности

Runner реализует принцип минимальных полномочий.

1. `agy` запускается через `subprocess` без оболочки и без `shell=True`.
2. Стандартный ввод закрыт, поэтому headless-процесс не зависает в ожидании интерактивного ввода.
3. Флаг `--sandbox` включается всегда.
4. Флаг `--dangerously-skip-permissions` намеренно не поддерживается.
5. Распространённые переменные окружения с токенами, паролями и ключами удаляются перед запуском дочернего процесса.
6. Исходный репозиторий должен быть чистым.
7. Режим `read-only` использует временный detached worktree и удаляет его после завершения.
8. Любая запись в режиме `read-only` считается нарушением политики, даже если основной checkout не пострадал.
9. Режим `isolated-write` создаёт отдельную ветку и worktree; агент не получает основной checkout.
10. Runner не выполняет commit, merge, push, deploy или миграции.
11. Текст задания не записывается в результат; сохраняются только длина и SHA-256.
12. Постоянные журналы создаются только по явному параметру пользователя и с ограниченными правами доступа.

Ограничение: sandbox и permission engine принадлежат Antigravity CLI. Пользователь обязан настроить точечные allow/deny-правила в `~/.gemini/antigravity-cli/settings.json` и проверить их для своей версии CLI.
